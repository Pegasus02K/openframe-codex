# OpenFrame 7.3 제품별 저장소 빌드

7.3 프로필의 제품별 저장소에 적용한다. 7.4는 [통합 빌드](build-74.md)를 따른다.

## 소스와 설정

- 요청한 버전·OS에 필요한 제품과 저장소 URL·브랜치는 현재 사용자 지시, 제품 메타데이터와 저장소에서 확인한다. 과거 실행의 브랜치를 기본값으로 고정하지 않는다.
- 제품별 SSH 주소 형식은 `ssh://git@192.168.51.106:2022/openframe/openframe7/<제품>.git`이다. 필요한 제품의 실제 저장소와 접근 권한을 확인하고 사용한다. 주소가 변경된 경우 서버의 현재 clone 주소를 따른다.
- 제품별 저장소를 준비하고 `$SOURCE_BASE` 아래 실제 디렉터리 구조를 확인한다. 각 제품의 `AGENTS.md`, Makefile, 설정 샘플과 release 스크립트를 읽는다.
- 제품별 release 스크립트를 해당 제품이 요구하는 위치에서 실행한다. 공용 도구·스크립트를 덮어쓰는 동작이 있으면 기존 파일을 보존하고 작업 후 복원한다.
- 현재 플랫폼 설정과 샘플을 기준으로 로컬 설정을 생성한다. OS·DB·COBOL·Sort 선택을 실제 환경과 맞추고 상호 배타적 스위치와 미해결 토큰을 점검한다.
- 추가 제품의 헤더·라이브러리 의존성은 실제 Makefile과 오류에서 확인한다. 헤더 준비와 해당 제품 빌드·설치 필요성을 구분한다.

## 전처리·빌드·설치

- 선택 DB 전처리기의 cfg·include·라이브러리를 실제 설치 경로에 맞춘다. GCC include는 `gcc -print-file-name=include` 결과와 파일 존재로 확인한다.
- 각 Makefile의 실제 `.tbc`/`.pc` 입력과 target을 확인해 필요한 디렉터리에서 `make precomp`를 수행한다. 루트 target 부재나 적용할 입력이 없는 경우는 성공과 구분하고, 필요한 입력이 누락되면 중단해 확인한다.
- 공통 라이브러리와 제품 간 의존 순서를 현재 Makefile에서 확인하고 빌드·설치한다. 컴파일 옵션 보완은 현재 컴파일러와 실패 근거로 결정하며 제품 소스 변경으로 우회하지 않는다.
- 전처리 cfg가 설치본의 런타임 컴파일에도 사용되면 소스와 설치본 모두 유효한지 확인한다.
- 라이선스 도구의 목적지를 신규 설치에 지정하고 필요한 제품의 라이선스를 생성한다.
- 생성된 Tmax 설정은 대상 OS·포함 서버·경로를 확인해 선택한다. 파일명이나 생성시각만으로 판단하지 않는다.
