# OpenFrame 7 빌드

루트 `AGENTS.md`에 따라 환경 프로필을 선택하고 실제 소스의 하위 지침을 적용한다. 구체적인 버전·OS·DB·컴파일러·브랜치·경로는 현재 세션의 요청과 선택한 환경에서 확인한다.

## 준비

- 기존 저장소는 루트 지침에 따라 상태 확인과 `git pull --ff-only`를 먼저 수행한다.
- OpenFrame 소스의 clone·fetch·pull은 SSH를 사용한다. 실행 환경의 remote 주소·Git SSH 인증을 확인하고 버전별 참조의 저장소 경로를 사용한다. HTTP remote가 남아 있으면 루트 지침에 따라 전환 범위를 확인하며 인증 실패를 HTTP로 우회하지 않는다.
- 새 환경이 필요하면 소스·설치·환경 파일 경로를 정하고 기존 환경과 충돌하지 않는지 확인한다. 기존 소스·설치를 덮어쓰지 않고 개인 YAML은 요청 범위에서만 변경한다.
- 배포본·라이선스·DB 클라이언트/ODBC·연결 확인과 패키지 설치는 `openframe7-setup`의 설치 전 확인을 따른다.
- 인증은 대화형 프롬프트로 전달하며 credential 파일·URL·환경 변수·로그·스킬에 저장하지 않는다.

## 빌드·설치와 보고

- 실제 Makefile의 의존 순서로 빌드·설치하고 로그·종료 코드·산출물을 확인한다.
- 실패하면 현재 로그에서 원인을 좁힌다. 의존 도구·헤더·라이브러리 또는 제품 제외가 필요하면 해당 세션에서 범위와 조치를 사용자와 확인한다. 빌드 요청만으로 제품 소스 변경을 진행하지 않는다.
- 라이선스 도구의 설치 목적지를 명시해 공용 도구를 덮어쓰지 않고, 필요한 제품 라이선스와 최종 Tmax 설정을 확인한다.
- DB 초기화·기동·실행 검증은 `openframe7-setup`으로 이어간다. 빌드·설치·런타임 검증 결과를 구분한다.
- 실제 환경, 브랜치/커밋, 경로, 실행 명령, 성공·실패·미검증 범위는 현재 세션에서 사용자에게 보고한다. 개별 실행 결과를 지침이나 스킬에 누적하지 않는다.
